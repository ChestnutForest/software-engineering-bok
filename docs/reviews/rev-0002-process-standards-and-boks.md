# REV-0002 プロセス標準と知識体系の追加に対する検証

## 1. 検証の対象

次の問いに対して生成された回答を検証した。

> 多岐にわたるメソドロジーに SEI の CMMI や PSP や TSP、People CMM、ISO9000、
> SEBOK などのメソドロジーを加えた場合、GitHub の適切で最適なリポジトリの
> ネーミングを絞ってほしい。

回答の骨子は次のとおりである。

1. 【圧倒的最適】`software-engineering-bok`（または `swe-bok`）
2. `software-process-engineering`
3. `se-standards-and-practices`
4. 組織・システム・チーム・設計実装・個人の5層マッピングを提示

## 2. 判定の要約

| # | 指摘 | 重大度 |
| --- | --- | --- |
| 1 | SEBoK は別分野の知識体系であり、第1位の論拠が逆転している | 重大 |
| 2 | 権利関係にまったく触れていない。本リポジトリで最も制約が強い対象が含まれる | 重大 |
| 3 | BoK の性格の取り違えが再発している | 重大 |
| 4 | ISO 9000 と CMMI をメソドロジーとして扱っている | 重大 |
| 5 | 個人プロジェクトに適用できない対象を選択肢として扱っている | 中 |
| 6 | 名称・策定主体・現況に誤りと表記ゆれがある | 中 |
| 7 | 5層マッピングが REV-0001 の6軸と整合しない | 中 |
| 8 | 名前が決定済みである事実を参照していない | 小 |

結論を先に述べる。**第1位の結論そのものは正しいが、理由が誤っている。** 加えて、
採用可否を左右する論点（権利関係）が丸ごと抜けている。

## 3. 重大な指摘

### 3.1 SEBoK は別分野の知識体系であり、論拠が逆転している

回答は「SEBOK がスコープに入ったことで `software-engineering-bok` が最も自然で
説得力のあるネーミングになる」と述べている。**これは逆である。**

- **SWEBOK Guide** は IEEE Computer Society が刊行する**ソフトウェア工学**の知識体系である。
- **SEBoK**（Guide to the Systems Engineering Body of Knowledge）は**システムズ
  エンジニアリング**の知識体系である。BKCASE プロジェクトの成果物で、INCOSE、
  IEEE Systems Council、Stevens Institute / SERC の3者が steward を務める wiki である。

両者は**別分野の、別団体による、別の知識体系**である。SWEBOK Guide は自らの目的の
1つに「他分野との境界を明確にすること」を掲げており、システムズエンジニアリングは
定義せずに関連分野として認識するにとどめている。

したがって、`software-engineering-bok` という名前のリポジトリに SEBoK の内容を
入れることは、**SWEBOK が意図的に引いた境界を壊す行為**である。SEBoK の追加は
この名前を補強するのではなく、むしろ**不整合を生む**。

なお SysML も同じ側にある。OMG の SysML はシステムズエンジニアリング向けの
UML プロファイルであり、SEBoK の文脈に属する。

### 3.2 権利関係にまったく触れていない

これが本検証における最大の欠落である。今回追加された対象は、本リポジトリが
これまで扱ってきたどの資料よりも**制約が強い**。

| 対象 | 権利者 | 制約 |
| --- | --- | --- |
| ISO 9000 ファミリー | ISO（国内は日本規格協会） | **有料の規格票。本文の複製・再配布はできない。** 言及は規格番号と表題にとどめる |
| CMMI | ISACA（商標は CMU が USPTO に登録） | モデル本文は有償ライセンス。「CMMI」は登録商標 |
| **PSP / TSP** | **カーネギーメロン大学** | **PSP・TSP は CMU のサービスマーク。** Process Dashboard 同梱のスクリプトとフォームは**個人利用限定の特別許諾**であり、**派生や改変には SEI の書面許可が必要**。2018年に CC BY 4.0 で公開された教材が別に存在する |
| People CMM | CMU / SEI | 技術報告書ごとに配布条件を確認する必要がある |
| SEBoK | BKCASE（INCOSE / IEEE-SYSC / Stevens） | 無償公開だが著作権表示と引用規定がある |
| SWEBOK Guide | IEEE Computer Society | 無償で入手できるが本文は著作物 |
| RUP | IBM | proprietary |

回答は PSP と TSP を「個人の品質・規律層（Micro）」として無批判に並べている。
しかし**この2つは本リポジトリが扱う対象のなかで最も制約が強い。** 姉妹プロジェクト
Processloop で、PSP/TSP のスクリプトとフォームの許諾条件を理由に公開可否の
ゲートを設けているのと同じ制約が、ここにもそのまま適用される。

**回答の結び「世界的にも価値が高く、非常に有意義な知識集約の場になる」は、
その集約が本文の転記を含むなら成立しない。** 公開できないからである。

ADR-0001 第4.1章、REV-0001 第5.1章に続き、**3回連続で同じ観点が抜けている。**

### 3.3 BoK の性格の取り違えが再発している

回答は「BoK はまさに『どの知識を、いつ、どのように適用するか』を定義するもの」と
述べている。これは REV-0001 第4.1章で訂正済みの誤りの再発である。

SEBoK 自身が「compendium（集大成）ではなく、既存の文献を参照するもの」と明記している。
SWEBOK Guide も同様に、主要概念を要約して参考文献の一覧を示す構成である。

**BoK は指し示すための記述的な文書であって、選択を助ける規範的な文書ではない。**
「圧倒的最適」とする論拠の中核が、事実と食い違っている。

### 3.4 ISO 9000 と CMMI をメソドロジーとして扱っている

回答は冒頭でこれらを「メソドロジー」と総称している。実際には種別が異なる。

- **ISO 9001** は品質マネジメントシステムの**要求事項**であり、**第三者認証の対象**である。
  開発手法ではない。ソフトウェアへの適用指針は別途 ISO/IEC 90003 が定める。
- **CMMI** は組織のプロセス能力を**評定（appraisal）**する枠組みである。米国政府調達で
  要求されることがある。これも開発手法ではない。
- **People CMM** は人材面の成熟度モデルである。

REV-0001 第3.4章で指摘した「層が違うものを同一平面に並べている」という問題が、
より広い範囲で再発している。今回は**工程の層だけでなく、適用範囲の層（組織／
チーム／個人）と、種別の層（手法／標準／認証制度）**が混ざっている。

### 3.5 個人プロジェクトに適用できない対象を選択肢として扱っている

本リポジトリの運用主体は個人である。ADR-0001 が引用したとおり、IPA の機能要件の
合意形成ガイドは 300ファンクションポイント以上、10名以上、50人月以上を想定して
おり、この想定から外れていることを姉妹プロジェクトは明記している。

同じことが今回の追加分にも当てはまる。

| 対象 | 個人プロジェクトへの適用 |
| --- | --- |
| CMMI の評定 | **不可能。** 組織単位の評定制度である |
| ISO 9001 の認証 | **不可能。** 組織単位の認証制度である |
| People CMM | **不可能。** 人材マネジメントの成熟度モデルである |
| TSP | **不可能。** チームを前提とする |
| PSP | **可能。** 個人の計測を対象とする |

**適用できないものを「選択ガイド」に載せても選べない。** これらは選択肢ではなく、
考え方を知るための参照として登録すべきである。回答はこの区別をしていない。

## 4. 名称・策定主体・現況の訂正

| 回答の表記 | 正しい表記 | 策定・管理 | 現況 |
| --- | --- | --- | --- |
| SEBOK（システムエンジニアリング知識体系） | **SEBoK**（Guide to the Systems Engineering Body of Knowledge、**システムズ**エンジニアリング） | BKCASE。INCOSE / IEEE Systems Council / Stevens Institute（SERC） | wiki として継続更新。v2.13 |
| CMMI（SEI） | CMMI（Capability Maturity Model Integration） | CMU で開発。2012年に CMMI Institute 設立、**2016年3月に ISACA が買収** | **V3.0（2023年4月）。** People Management、Data Management、Virtual Work の3ドメインが追加された |
| PeopleCMM | **People CMM**（P-CMM） | CMU / SEI | 独立モデルとしては旧世代。人材面は CMMI V3.0 の People Management ドメインが担う（要確認） |
| ISO9000 | **ISO 9000 ファミリー** | ISO | ISO 9000 は用語と基本、**ISO 9001 が要求事項**。ソフトウェアへの適用指針は ISO/IEC 90003、ライフサイクルプロセスは ISO/IEC/IEEE 12207、プロセスアセスメントは ISO/IEC 33000 シリーズ |
| SWEBOK | SWEBOK Guide | IEEE Computer Society | V4.0（2024年） |

回答は CMMI を「カーネギーメロン大学ソフトウェア工学研究所（SEI）の思想」として
説明している。起源としては正しいが、**現在の管理主体は ISACA である。** 商標は
CMU が保持しているため、権利関係は2者にまたがる。本リポジトリでは両方を記す。

## 5. 5層マッピングの評価

回答が示した5層マッピングは、着想としては有用だが、そのままでは採用できない。

| 回答の層 | 判定 |
| --- | --- |
| 組織・品質マネジメント層（ISO9000, CMMI, People CMM） | 妥当 |
| システム全体のアーキテクチャ層（SEBOK, SysML, SPLE） | **不可。** SEBoK は知識体系であって層に置くものではない。SysML は記法、SPLE は再利用戦略で、3つとも種別が異なる |
| チーム開発プロセス層（RUP, TSP） | 妥当 |
| ソフトウェア設計・実装層（DDD, OOP, 構造化手法, AI駆動） | 妥当 |
| 個人の品質・規律層（PSP, TDD, Spec駆動） | **要修正。** Spec 駆動は個人の規律ではなくエージェントへの指示の与え方である |

**重要なのは、この5層が REV-0001 第7章で決めた6軸とは別の切り口だという点である。**
5層は「適用範囲（組織／チーム／個人）」の階層であり、パラダイムや記法といった軸とは
直交する。**置き換えるのではなく、7番目の軸として追加するのが正しい扱いである。**

## 6. 本リポジトリへ反映する決定

| # | 決定 |
| --- | --- |
| 1 | **リポジトリ名は変更しない。** ADR-0001 の決定を維持する（3度目の確認） |
| 2 | **SEBoK は「関連分野」として扱う。** 本文は置かず、リンクと、ソフトウェア工学との境界の記述だけを置く |
| 3 | **登録フォーマットに `rights` 欄を必須で設ける。** 権利者と制約を書けない項目は登録しない |
| 4 | REV-0001 の6軸に、**第7軸「適用範囲」を追加する** |
| 5 | 個人プロジェクトに適用できないものは、**選択肢ではなく参照として登録する** |
| 6 | **PSP / TSP は最も制約が強い対象として個別に扱う。** サービスマークの表示と、参照してよい版（2018年の CC BY 4.0 版か、特別許諾版か）を明記する |

第7軸の定義は次のとおりとする。

| 軸 | 選択肢の例 | 性質 |
| --- | --- | --- |
| 適用範囲 | 組織（CMMI、ISO 9001、People CMM）/ チーム（TSP、RUP、スクラム）/ 個人（PSP、TDD） | 階層。上位が下位を含む。個人プロジェクトでは組織層を選べない |

## 7. ADR-0001 の未決事項への影響

| # | 未決事項 | 本検証による変化 |
| --- | --- | --- |
| 1 | 上流工程を含むかどうか | **問いの立て方を変える必要が生じた。** CMMI や ISO 9001 は工程の枠外にある。境界は「工程」ではなく「適用範囲と対象分野」で引く |
| 2 | 複数工程にまたがる手法の置き場 | 変化なし |
| 3 | `references-usdm-ipa.md` の移設可否 | 変化なし |
| 4 | 文書の粒度と命名規則 | `rev-*` の連番運用を継続した |
| **5** | **ソフトウェア工学以外（システムズエンジニアリング、組織品質マネジメント）を含めるか** | **新規。** SEBoK、ISO 9001、People CMM の追加により発生した |

未決事項1と5は同じ ADR で片づけるのがよい。工程で切る案は第3.4章の理由により
採らず、**「適用範囲（組織／チーム／個人）×対象分野（ソフトウェア工学／システムズ
エンジニアリング／品質マネジメント）」の2軸で境界を定義する**案を検討すること。
