# REV-0011 IPA 2資料の組み入れに向けた全体整合性の再検証

## 1. 結論

**2資料を一次情報の参照項目として組み入れる方針は妥当である。ただし、REV-0010 をそのまま登録仕様にしてはいけない。** 使用条件の欠落、後継関係の過大な断定、確認状態と選択可否の混同を修正する必要がある。

今回の依頼により、少なくとも機能要件の合意形成ガイドと発注者ビューガイドラインを収録対象とする意向は明らかになった。「上流を含むか未決なのでこの2件も検討できない」という議論を繰り返さず、2件の収録範囲を決定記録へ反映する。その他すべての上流手法や関連分野まで承認されたとは解釈しない。

本書は検証結果と修正案である。**手法エントリの登録、ADR・スキーマの確定は未実施**（2026-09-19にREV-0010へWARP再確認による訂正注記を追加）であり、本書の追加だけを「IPAガイドの組み入れ完了」としない。

## 4. 修正すべき事項

優先度は、P1=正式登録前に修正、P2=登録仕様を固めるまでに修正、P3=編集上の訂正、とする。以下の行番号は基準コミットの位置を指す。

### F01 / P1 使用条件から再配布先の遵守条件が抜けている

**対象:** REV-0010 §3.1、§4.2（149〜156行）、§7.1（289〜296行）。

`rights.conditions` は著作権表示・対象者・目的だけを記し、配布先の遵守条件と無償性を完全には保持していない。また `derivation: prohibited` だけでは原文にある許可・法令上の留保が読めない。

**修正:** 利用条件のURLとページを必須にし、要約欄には無償性、配布先の遵守、対象者、目的、表示条件を含める。値は「無条件に不可」ではなく、少なくとも「公開許諾では認められていない」と読める定義にする。PDFのGitHub再配布は今回行わず、書誌とリンクを収録する。

**完了条件:** 条件欄を見た利用者が「著作権表示だけで自由に転載できる」と解釈しない。

### F02 / P1 参照先の権利とリポジトリ自作部分のライセンスを混同している

**対象:** README「ライセンス」、REV-0009 §3.2、REV-0010 §10（380行）。

「IPA資料が翻案不可だからリポジトリのMITと整合しない」は、リンク・書誌を置く場合と、第三者本文を収録する場合を混同している。[MIT原文](https://opensource.org/license/mit)は関連文書にも言及するため、「文書だからMITは使えない」とも結論できない。

**修正提案:** 自作部分への許諾と外部資料の条件を明示的に分離する。外部資料の権利をMITで再許諾するものではないとREADMEに記す。CC BYへの変更を検討すること自体は可能だが、変更するだけで第三者資料の扱いが解決するわけではない。LICENSEの変更はこの検証の結果として自動実施しない。

これは参照物を同梱していない現状とライセンス原文に基づく整理であり、第三者本文の転載一般を適法と認定するものではない。

### F03 / P1 前身資料の未確認と、収録・選択の可否を混同している

**対象:** REV-0010 §3.3（106〜126行）、§4.5、§7.2。

今回確認できたのは「改訂版・前身」という関係であり、全内容の包含や互換性ではない。**技術領域が増えたことだけでは上位互換の証明にならない。** 同様に、旧資料であることや手動確認が必要なことから、永久に `registered` 不可とは導けない。

**修正（2026-09-19更新）:** IPAの2008年7月版4分冊については、本文の対象箇所・使用条件の未確認を理由から外す。`referenced-only` を用いる場合は「今回は系譜の参照項目とするという収録方針で、正式登録規約は未確定」とする。確認済みであることだけから自動的に `registered` へ変更もしない。関係の根拠は2008年公開案内と2010年版の改訂記載とし、全面的な上位互換や正式廃止は未確認とする。

### F04 / P1 外部設計への配置訂正が統合構成案まで届いていない

**対象:** REV-0004 §4（116行）、REV-0008 §7（220行）、REV-0006 §10、REV-0007 §9。

REV-0010はREV-0004の配置を訂正したが、REV-0008の「統合版」も `requirements/ipa-agreement-guide.md` を保持している。新しい読者が統合版を起点にすると同じ誤配置を再現する。

**修正:** 2資料の候補配置を `40-software/design/` に揃える。旧REVを残す場合は冒頭に訂正先をリンクし、現行の構成を定める文書を1つにする。`requirements/` 側には必要なら参照リンクだけを置く。

### F05 / P1 READMEが公開版・ローカル版とも既存の訂正に追随していない

**対象:** README「現在の状態」「検証記録」「姉妹リポジトリ」。

- 基準コミットにはREVが10本あるが、READMEの本数は9本で、REV-0010へのリンクがない。
- 公開READMEは `paper-repro` と `paper-repro-mvp` を別リポジトリと述べる。訂正済みREV-0009 §2と矛盾する。
- ローカルの未コミット変更も「旧版」としており、「同一リポジトリの旧名」とするREV-0009の訂正内容と一致しない。

**修正:** REV-0010と本書へのリンクを追加し、本書追加後は11本にする。改名の説明をREV-0009と同期する。IPAの手法エントリはまだ作成していないため、「収録は始まっていない」を不用意に完了へ変えない。

### F06 / P2 確認方法・取得結果・権利確認日が混ざっている

**対象:** REV-0010 §5、§7.1、§8の決定8。

`verify: manual` は確認方法であって、確認済みの証拠ではない。姉妹プロジェクトの2026-08-24という確認日を、自分が確認した日として移すべきではない。権利確認日の横に条件ページがなく、再確認も難しい。

**修正:** 確認方法、最終試行日、成功した確認日、結果、確認範囲を分ける。リンクへの到達、本文の確認、使用条件の確認を区別する。手動確認URLはネットワーク検査だけを対象外にし、URL形式、必須項目、相対リンク、ID整合性の検査は続ける。生成処理と外部ネットワーク検査も分離する。

### F07 / P2 メタデータの型と正本が未確定である

**対象:** REV-0003〜0010の登録例全般。

`sources` は文字列配列からオブジェクト配列へ変化し、`target_phase` は文字列と配列が混在する。`applicable_to_solo` は真偽値と `partial` の混合で、未確認を表せない。`verified` に日付と「未確認」が入り、`MTH-00NN` が双方のIDとして繰り返される。これは現時点では例示だが、そのまま収録すると自己参照・重複IDになる。

**修正案:** 工程は常に文字列配列、適用性は文字列列挙、未確認日付はnull、出典は構造化配列に揃える。IDを正式採番し、実在する別エントリを参照させる。`docs/conventions/method-entry-format.md` に正本を設け、過去の例は旧形式と明記する。規約と検査は未実装なので「欄を提案したから構造的に解決済み」としない。

### F08 / P2 個人開発への適用性と、資料の想定・登録可否を分離する

**対象:** REV-0002 §3.5、REV-0010 §4.3、§7。

IPAの規模想定を必須条件にしない。また「個人開発」でも外部の顧客や利用者が存在する場合がある。「個人なら発注者と開発者は必ず同一」ではない。自己レビューへの読み替えと、外部の利害関係者との合意を区別する。

**修正:** ガイド本来の対象、プロジェクトの当事者構成、今回採用する観点、採用しない範囲を個別に記録する。`partial` の理由を資料自体の欠陥や利用禁止と混同しない。

### F09 / P2 手法関係の語彙と参照箇所が一致していない

**対象:** REV-0005 §6.2、REV-0008 §6.3、REV-0010 §3.3（125行）。

`succeeds` の初出はREV-0005 §6.2であり、REV-0010の「REV-0007で定めた」は参照誤り。またREV-0008は「Zの影響」を `succeeds` と表し、REV-0010では同じ語を資料の後継関係に使う。影響を受けたことと、置き換えることは異なる。

**修正:** `influenced-by`、`revised-from` 等を検討し、関係の向き・意味・根拠を規約で定義する。逆関係を両方保存するか、一方から生成するかも決める。新たな語彙は本書の提案であり、採用済みと扱わない。

### F10 / P2 CMMIの成熟度レベルに関する訂正が誤っている

**対象:** REV-0003 §5（108行）。

「レベル4はV1.3の語で、V3.0はドメインとプラクティスエリア」という対比は、成熟度レベルがなくなったように読める。[CMMI公式のレベル説明](https://cmmiinstitute.com/learning/appraisals/levels)には現在も成熟度レベル4・5がある。能力レベルと成熟度レベルを区別する。

**修正:** 元の提案に「レベル4以上を前提とする根拠がない」という批判は残せるが、レベルの不存在を理由にしない。バージョン、評定の対象、選択ガイド上の運用制限を分けて書く。

### F11 / P2 SysMLを版なしでUMLプロファイルに分類している

**対象:** REV-0001 §3.4（95行）、REV-0002 §3.1、REV-0008 §2。

[OMG公式](https://www.omg.org/sysml/sysmlv2/)はSysML v2をKerMLに基づく言語として説明し、形式的意味論に言及している。UMLプロファイルという説明はv1系に限定すべきである。版なしの `semi-formal` 一括分類も再検討が必要。

**修正:** 参照する版と仕様URLを必須にし、v1とv2を区別する。形式的意味論を持つことだけから、対象モデルの安全性を自動証明できるとは書かない。検証可能な性質と必要なツールを別に記録する。

### F12 / P3 公式名称の裏づけと、断定の範囲を修正する

**対象:** REV-0010 §6・§7.2（314行）、起点資料の冒頭注意書き。

`Vendor View Guideline` は発注者側を表す名称として不適切であり、公式英語名としての根拠も示されていない。日本語名を正式名称とし、英語名は未確認とする。ファイル名には公式訳を装わない `ipa-hatchusha-view-guideline.md` を候補とする。

また起点資料は冒頭で「章立てだけの間接採用」としながら、第2節では2026-08-26から直接採用と記載する。一般参照集へ丸ごと移設するとこの不整合とプロジェクト固有の採用判断を持ち込む。書誌・利用条件のみを抽出し、個別プロジェクトの採用履歴はリンクで参照する。

### 5.3 スキーマに要求すること

1. 種別 `guideline`、対象工程 `external-design`、公開年・版を表現できる。
2. 登録状態、資料の新旧、適用性、出典の確認状態を独立に持つ。
3. 著作権者と策定団体を区別し、使用条件は資料・版単位で記録する。
4. 入手可能性、複製、再配布、改変を区別する。無償入手できることを再配布許可と扱わない。
5. 元資料の条件と、本リポジトリの「本文を載せない」方針を分ける。
6. 条件を確認した資料URL、位置、確認日を追跡できる。
7. 旧版本文の取得に失敗しても、確認済みの後継資料から系譜を記録できる。
8. `MTH-00NN` のような例示IDは本登録で許容しない。
