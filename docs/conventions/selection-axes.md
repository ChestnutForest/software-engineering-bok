# 選択の軸

**この文書はプロジェクトが選ぶ側の枠組みである。** 手法エントリの Front Matter には
入れない。手法は軸の値を持つのではなく、**軸のどれか1つそのもの**である。

UML はパラダイムを持たない。UML が記法なのである。それは `kind` が表す。

## 8つの軸

| 軸 | 選択肢の例 | 排他性 |
| --- | --- | --- |
| パラダイム | 構造化 / オブジェクト指向 / 関数型 | ほぼ排他 |
| 設計アプローチ | DDD / トランザクションスクリプト | 部分的に排他 |
| プロセス | RUP / TSP / XDDP / スクラム / V字 | ほぼ排他 |
| 記法 | UML / SysML / PFD / Mermaid / USDM | 併用できる |
| 再利用戦略 | SPLE / 都度開発 | 排他 |
| 実装プラクティス | PSP / TDD / 仕様駆動 | 併用できる |
| 適用範囲 | 組織 / チーム / 個人 | 階層。上位が下位を含む |
| 開発の起点 | 新規 / 派生 / 両方 | 排他 |

## 単一選択ではない

**「どの手法を選ぶか」という問いは成立しない。** DDD と UML と TDD は1つの
プロダクトで同時に使える。正しい問いは「どの軸で何を選び、どう組み合わせるか」である。

したがって選択ガイドは**1枚の表にならない。** 軸ごとの手順として書く。

## 軸のあいだの依存

軸を独立に選べるわけではない。

| 依存 | 内容 |
| --- | --- |
| DDD → オブジェクト指向 | DDD はオブジェクト指向を前提とする |
| XDDP → 母体 | 母体が無いと適用できない |
| TSP → PSP | PSP を修めた技術者を前提とする |
| SysML → システムズエンジニアリング | その文脈を前提とする |

## `origin` は先に決まる

**「新規開発か派生開発か」は他の軸より先に決まる。**
`derivative` なら、プロセスは XDDP に絞られ、再利用戦略に SPLE が候補として立つ。

## 適用範囲の制約

個人プロジェクトでは組織層を選べない。CMMI の評定も ISO 9001 の認証も
TSP も、組織やチームが無いと成立しない。
