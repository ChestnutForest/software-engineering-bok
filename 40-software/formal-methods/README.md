# formal-methods — 数学的な意味論を持つ記述

## 置くもの

| 手法 | 基礎 | 検証の方法 | 範囲 |
| --- | --- | --- | --- |
| [Z 記法](z-notation.md) | ZF 集合論と一階述語論理 | 定理証明 | 無限 |
| [VDM](vdm.md) | モデルベース仕様 | 証明と検査 | 無限 |
| [Alloy](alloy.md) | 一階関係論理 | SAT による探索 | **有界** |
| [TLA+](tla-plus.md) | 時相論理と集合論 | モデル検査と証明 | TLC は有限、TLAPS は無限 |

**4つを一括りにできない。** 何を確かめたいかで分かれる。

- **Alloy は証明する道具ではない。** 指定した有限の範囲で反例を探す。
  反例が見つからないことは、その範囲で見つからなかったという意味である
- **TLA+ の TLC も有限状態の探索である。** 無限の状態空間に対する証明は TLAPS が担う

## サブディレクトリに分けない

「状態ベース（Z、VDM）」と「時相・並行（TLA+）」に分けたくなるが**分けない。**
1つの分類を木に焼き付けると、他の分類が見えなくなる。
違いは上の表と、各エントリの `verification` 欄で表す。

## これらが形式手法でない理由

次の4つは `semi-formal` であり、**形式手法ではない。**

| 対象 | 実体 |
| --- | --- |
| USDM | 要求を階層化する記述法。構造化された自然言語である |
| UML / SysML | モデリング言語。意味論は数学的に定義されていない |
| PFD | 成果物と作業を矢印で結ぶ図法 |
| SPEM | MOF にもとづくメタモデル。構造を定義する |

**記述の厳密さと、検証の可能性は別のことである。** これらを Z や Alloy になぞらえると、
読み手は機械的な検査ができると期待してしまう。

この取り違えは過去に3回起きた（USDM、PFD、SPEM）。**`formality` 欄は、
それを構造的に防ぐために設けた。**

## 権利

**Z と VDM は同じ ISO 規格でありながら入手条件が違う。**

| 対象 | 入手 |
| --- | --- |
| Z（ISO/IEC 13568:2002） | ISO の ITTF サイトから無償で入手できる。要確認 |
| VDM（ISO/IEC 13817-1:1996） | 購入が必要と見られる。要確認 |

**ISO 規格を一律に扱わない。**
