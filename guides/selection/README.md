# 手法の選び方

**単一の表では選べない。** 軸ごとに順番に決める。
軸の定義は [`../../docs/conventions/selection-axes.md`](../../docs/conventions/selection-axes.md) にある。

## 手順

### 1. `origin` を決める — 新規か、派生か

**これが他の軸より先に決まる。**

| 答え | 効果 |
| --- | --- |
| 新規（greenfield） | XDDP は選べない。SPLE は「これから資産を作る」側で検討する |
| 派生（derivative） | プロセスは XDDP が候補。SPLE が再利用戦略の候補に立つ |

### 2. 適用範囲を確かめる — 組織か、チームか、個人か

| 範囲 | 選べるもの |
| --- | --- |
| 個人 | PSP、TDD、USDM、記法、形式手法 |
| チーム | 上記＋ RUP、TSP、XDDP |
| 組織 | 上記＋ CMMI、ISO 9001、People CMM、SPLE |

**上位が下位を含む。** 個人プロジェクトでは組織層を選べない。

### 3. パラダイムを決める

構造化かオブジェクト指向か。**ほぼ排他である。**
DDD を採るならオブジェクト指向が前提になる。

### 4. プロセスを決める

`origin` と適用範囲で候補が絞られている。

### 5. 記法を決める

**併用できる。** UML と Mermaid と USDM を同時に使ってよい。
対象が違うためである（ソフトウェア / 図 / 要求）。

### 6. 実装プラクティスを決める

**併用できる。** TDD と仕様駆動を同時に使ってよい。

### 7. 形式手法が要るかを判断する

要るなら、**何を確かめたいか**で選ぶ。

| 確かめたいこと | 手法 |
| --- | --- |
| 仕様の矛盾 | Z |
| 実装への詳細化の誤り | VDM |
| 設計の構造と制約（有界な反例探し） | Alloy |
| 並行・分散系の安全性と活性 | TLA+ |

## 制約

両立しない組み合わせは [combinations.md](combinations.md) にある。
